# Firebase Cloud Messaging для Android

Рабочая копия от 22.10.2026. Клиентская интеграция и серверный отправитель реализованы. Рабочий сервер обновлён, ключ подключён. На физическом Pixel 8 проверены настоящая доставка двух сообщений, системное уведомление и входящий звонок через FCM без фонового WebSocket. Клиентское обновление не опубликовано.

## Клиент

- Пакет: `app.neochat`. Локальная конфигурация пользователя скопирована в `apps/android/app/google-services.json`; она исключена из Git. На CI файл нужно предоставлять отдельно. При его отсутствии Google Services plugin не применяется, Firebase не регистрируется, обычная синхронизация продолжает работать.
- Google Services plugin — 4.5.0; Firebase BoM — 35.0.2, Messaging — 26.0.0. Используется текущий API `register()` / `onRegistered()` с Firebase Installation ID. SDK Messaging имеет лицензию Apache-2.0; отдельный Analytics SDK не добавлен, сбор Analytics выключен.
- Идентификатор установки регистрируется через существующий авторизованный `set_push_token`. Его владельцем сервер считает текущее устройство сессии. Повтор после открытия приложения, входа или восстановления подключения обновляет регистрацию; значение не выводится в логи.
- В FCM передаётся только `{"type":"sync"}`. Текст, название чата, имя собеседника, ключи и ciphertext в push не отправляются. Клиент получает E2EE-сообщения и сигналы звонка обычным `sync_now`; затем существующий код показывает уведомление или входящий звонок.
- `FirebaseMessagingService` передаёт работу существующему `SyncJob`. На Android 12+ при доставленном high priority запрашивается expedited job, при отказе — обычная. Одновременные сигналы объединяются в одну ожидающую задачу. Фоновый WebSocket и периодическая синхронизация остаются дополнительными путями доставки.

## Сервер

Миграция `0009_push_jobs.sql` создаёт одно задание на устройство. Задание записывается в той же транзакции, что и событие зашифрованного сообщения. Повтор одного send не создаёт дополнительное задание; новый seq заменяет предыдущий. Одна фоновая задача обрабатывает ограниченные партии по 32 устройства через FCM HTTP v1. Ошибка сети, 429 или 5xx оставляет задание с задержкой повторения; подтверждённый `UNREGISTERED` удаляет регистрацию. Успех старого запроса не удаляет задание для более нового события. Выход и отзыв устройства удаляют его регистрацию и задания.

Для OAuth используется `golang.org/x/oauth2` 0.37.0 (BSD-3-Clause). Самодельного JWT или криптографии нет. Таймауты запросов и получения access token ограничены; ответы Firebase, токены и ключи не попадают в логи.

Переменная процесса сервера `GOOGLE_APPLICATION_CREDENTIALS` должна указывать на JSON сервисного аккаунта того же Firebase-проекта, например `/etc/neochat/firebase-adminsdk.json`. Это отдельный приватный серверный файл; `google-services.json` Android для отправки не подходит. Без переменной отправитель выключен. Доступ к файлу нужен только пользователю серверного процесса. Миграция применяется обычной командой `neochat migrate` или при старте `neochat serve`.

## Настроить в Firebase

1. Открыть настройки проекта → Cloud Messaging. Убедиться, что **Firebase Cloud Messaging API (V1)** включён. Если выключен — открыть управление API в Google Cloud и включить `fcm.googleapis.com`.
2. Настройки проекта → Service accounts → Firebase Admin SDK → Generate new private key. Сохранить JSON вне репозитория, например `E:/dev/keys/neochat-firebase-adminsdk.json`. Для последующей настройки сервера достаточно передать локальный путь к файлу; содержимое ключа не нужно вставлять в переписку.
3. Подключить файл к процессу сервера через `GOOGLE_APPLICATION_CREDENTIALS`, обновить сервер и применить миграцию. На рабочем сервере этот этап выполнен 22.10.2026, см. ниже.
4. Установить APK с конфигурацией Firebase, войти в аккаунт, разрешить уведомления Android. Проверить реальную доставку сообщения и входящего звонка при свёрнутом приложении и выключенном фоновом WebSocket. На устройстве нужны совместимые Google Play services. Задержки зависят также от сети, Android и приоритета, назначенного FCM; принудительная остановка приложения в настройках Android требует нового запуска приложения.

## Подключение рабочего сервера 22.10.2026

Предоставленный пользователем сервисный аккаунт соответствует проекту Android-конфигурации. Файл установлен вне репозитория: `/etc/neochat/firebase-adminsdk.json`, владелец `neochat:neochat`, права `0600`. Подключение задано отдельным systemd drop-in `/etc/systemd/system/neochat.service.d/firebase.conf`:

```ini
[Service]
Environment=GOOGLE_APPLICATION_CREDENTIALS=/etc/neochat/firebase-adminsdk.json
```

Drop-in сохраняется при замене основного unit-файла существующим `infra/deploy.sh`. Ключи и access token не выводились в терминал и не добавлялись в Git; временная серверная копия ключа удалена после установки.

Перед обновлением сохранены прежний бинарник и дамп БД в `/var/backups/neochat-releases/before-firebase-20261022/` (каталог `0700`, дамп `0600`, читаемость архива проверена `pg_restore --list`). Обновлён только сервер приложения и подключение Firebase; применена миграция `0009_push_jobs.sql`. SHA-256 установленного Linux/amd64-бинарника: `de5077a7238623bdfe5dbdbd513d1795bb9a83d89b107ac46c59f354abed1284`.

FCM HTTP v1 с `validate_only=true` вернул HTTP 200 сначала локально, затем с рабочего сервера от пользователя `neochat`. Это подтверждает доступность Google, действительность ключа, право отправки, включённый API и допустимость data-only запроса; доставка при такой проверке не выполняется. Включать дополнительные службы Firebase по результатам этой проверки не требуется. Firestore, Realtime Database, Authentication и Analytics для текущей схемы push не используются.

После перезапуска проверены локальный и публичный HTTPS `/health`, состояние `active/running`, код завершения `0` и отсутствие аварийных перезапусков. При подключении push-устройств ещё не было; после установки APK физический Pixel зарегистрировался. Успешный `validate_only` сам по себе не подтверждает регистрацию Android-устройства или доставку в фоне; отдельные проверки описаны ниже.

## Отладка на Pixel 8, Android 17, 22.10.2026

Первоначальная проверка установки оказалась недостаточной: после появления регистрации SDK приложение падало с `IllegalStateException: Must not be called on the main application thread`. По стеку R8 сбой происходил в `FirebaseMessaging.setAutoInitEnabled(true)`: режим FID синхронно читает установку, а callback `CoreClient.call` выполняется в главном потоке. Настройка auto-init и `register()` перенесены в рабочий поток; флаги регистрации остаются в главном потоке. Повторно собрана и установлена release/R8-сборка с sideload-подписью без удаления данных. После исправления проверены обычный запуск и запуск процесса через настоящий push без новых crash-записей.

С разрешения владельца использован отдельный тестовый аккаунт и отправлены ровно два тестовых сообщения и один короткий аудиозвонок. Перед отправкой через настройки выключено фоновое соединение; отсутствие `RealtimeService` подтверждено системной диагностикой. Проверены:

- Первое E2EE-сообщение в свёрнутом приложении: у отправителя статус `delivered`, в Android есть notification категории `msg`; JobScheduler зафиксировал запуск и завершение `SyncJob` с ID 2.
- Второе E2EE-сообщение: процесс приложения завершён обычным `am kill` (без force-stop), включён принудительный deep Doze. FCM запустил процесс и push-задачу; отправитель получил `delivered`, Android показал уведомление. Это функциональная проверка, без измерения задержки.
- Входящий аудиозвонок через настоящий WebRTC offer при выключенном экране, принудительном deep Doze и отсутствии фонового WebSocket: notification категории `call`, действия «Ответить» и «Отклонить». После проверки тестовый отправитель завершил звонок. На звонок не отвечали: соединение медиа, слышимость и камера этим сценарием не проверены.
- Серверная очередь после доставки пуста, регистрация устройства сохранена. Ключи, push-идентификаторы и содержимое переписки не выводились в диагностические отчёты.

Принудительный Doze после сценариев отключён. Исходная настройка «Мгновенная доставка» была включена; для изоляции FCM она временно выключена. Возврат переключателя и проверка вкладок на физическом телефоне ожидают разблокировки экрана владельцем; обход блокировки не выполняется. FCM остаётся зарегистрирован и работает при выключенном переключателе. Проверка не заменяет длительное испытание автономной работы, режима сна без USB и ограничений других производителей Android. Принудительная остановка приложения пользователем через настройки Android имеет другой смысл и в эти сценарии не входит.

## Проверки

`go test ./...` и `go vet ./...` запускаются в `server/`. Тесты БД используют только отдельную удаляемую базу через `NEOCHAT_TEST_DATABASE_URL`. Проверены payload без содержимого, ответы FCM, повторы send, откат транзакции, сохранение очереди после создания нового Server, ошибка с backoff, новое событие во время отправки, удаление устаревшей регистрации, права текущего устройства, выход и отзыв. Сеть Firebase заменена локальным HTTP-сервером; это проверка интеграционного кода, не настоящей доставки Google.

Проверка Android после `assembleDebug assembleDebugAndroidTest`:

```sh
adb -s emulator-5556 shell am instrument -w -e archive true -e push true app.neochat.test/app.neochat.ui.InteractionInstrumentation
```

Флаг `push` проверяет загрузку локальной Firebase-конфигурации, игнорирование неизвестного payload, создание expedited sync job и объединение серии сигналов. Настоящий FCM-вызов через Google для этой проверки не используется.

22.10.2026 пройдены `go test ./...`, `go vet ./...`, сборка сервера, Android `assembleDebug`, `assembleDebugAndroidTest`, `assembleRelease`, `lintDebug` и встроенный `lintVitalRelease`. Совместный прогон `-e archive true -e push true` прошёл на `Medium_Phone_API_36.1`, x86_64, с Google Play services. `lintDebug`: 0 ошибок, 83 предупреждения, включая устаревшую проверку AGP на `onNewToken` при использовании нового `onRegistered`. Это локальная сборка 0.6.7.3 (21). Размер подписанного arm64 APK измерен по длине файла после Release/R8: 22 782 566 байт; файл хранится в `apps/android/app/build/outputs/apk/release/app-release.apk`. Плавность и задержки доставки этими проверками не измерялись.
