# Организации

Оператор создаёт организацию командой `neochat create-organization "Название" "@владелец"` после миграции БД. Владельцем становится существующий аккаунт. Повтор команды с тем же названием и владельцем возвращает прежний ID. Назначение другого владельца этой командой отклоняется.

- `GET /v1/organizations` возвращает организации текущего пользователя и ожидающие приглашения. У принятого членства в ответе также есть ID привязанных канала и группы, если они настроены.
- `GET /v1/organizations/{id}/members` доступен участникам. Ожидающие приглашения видят владелец и администраторы.
- `GET /v1/users/{user}/organization-badges` возвращает авторизованному пользователю публичные значки администрации в формате `{"name":"Пример","emoji":"🏢"}`.
- `POST /v1/organization-badges` принимает до 64 идентификаторов в `user_ids` и возвращает для каждого владельца или администратора список организаций с названием и `icon_id`, если владелец загрузил изображение.
- `PUT /v1/organizations/{id}/icon` принимает бинарный PNG до 128×128 и 48 КБ только от владельца. `GET /v1/organization-icons/{id}` выдаёт текущий PNG авторизованному пользователю. При замене назначается новый ID.
- `POST /v1/organizations/{id}` принимает поле `action` и возвращает `204` при успехе. `invite` с полем `username` доступен владельцу и администраторам. Приглашённый использует `accept` или `decline`. Владелец использует `badge` с полем `badge`, `role` с полями `user_id` и `role` (`admin` или `member`), либо `link_channel` / `link_group` с полем `conversation_id`.

Владелец может создать отдельные канал и группу, передав `organization_id` в обычный запрос `POST /v1/conversations/groups`. Вместе с первой подписанной ревизией сервер атомарно привязывает чат к организации. У такой группы на момент создания может быть один участник. Привязка существующей беседы разрешена только её владельцу с совпадающим типом беседы.

Членство в организации и членство в её чатах проверяются независимо. Принятие приглашения не меняет состав канала и группы. Добавление в переписку проходит через прежний протокол подписанных ревизий.
