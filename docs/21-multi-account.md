# Несколько аккаунтов на одном устройстве

Изменение нативных клиентов Qt/Windows, Android и iOS. Не меняет опубликованную версию 0.6.8.2; для выпуска нужны отдельные сборки и публикация.

## Интерфейс

- «Настройки → Аккаунт → Сменить аккаунт» находится непосредственно над «Устройства».
- Переключатель показывает сохранённые аккаунты, текущий аккаунт и необходимость повторного входа. «Добавить аккаунт» открывает существующий сценарий входа/регистрации в отдельном локальном хранилище.
- На экране входа доступна кнопка «Сменить аккаунт», если есть другие сохранённые аккаунты: незавершённый вход не мешает вернуться к ним.
- Переключение не выполняет выход из других аккаунтов. После перезапуска восстанавливается последний выбранный аккаунт.
- На Desktop область списка устройств имеет высоту 208 логических пикселей: 3,5 строки по 58 px с промежутками 2 px. Даже с одним устройством область сохраняет эту высоту. При длинном списке видна часть следующей строки; при маленьком окне доступна прокрутка содержимого окна.

Используются существующие компоненты, клавиатурный фокус и настройки reduced motion. HTML-макет в `docs/design/` этим изменением не обновляется.

## Изоляция и доставка

Менеджер `core/src/accounts.rs` используется C ABI и JNI. Прежний аккаунт остаётся в `core/neochat.db`; остальные получают каталоги `core/accounts/<локальный UUID>/` с собственными SQLCipher-базами, Signal-состоянием, cursor, outbox, файлами и аватарами. Ключ доступа к базам остаётся защищён существующим платформенным хранилищем. Реестр локальных UUID и выбранный аккаунт находятся в отдельной таблице зашифрованной исходной базы, не в переносимой истории и не в серверном состоянии аккаунта.

Каждый аккаунт имеет свой worker. Изменение foreground, настройка фонового подключения, фоновая синхронизация и регистрация FCM применяются ко всем вошедшим аккаунтам. Ошибка одного аккаунта не прерывает обход остальных. Выход удаляет токены только выбранной сессии.

Нативные обёртки привязывают запрос к локальному аккаунту до запуска фоновой задачи. Служебное поле `_account_id` удаляется перед вызовом методов конкретного аккаунта и не уходит в API. Ответы предыдущего экрана отбрасываются после смены выбора; сохранение черновика при закрытии переписки явно обращается к её исходному аккаунту.

События содержат `account_id`. `account_selected` пересоздаёт или очищает экраны клиента; события невыбранного аккаунта не обновляют текущую переписку. Уведомления других аккаунтов приходят как `account_notify`. Уведомление хранит локальный ID аккаунта и ID переписки; открытие переключает аккаунт перед переходом в чат. Android/iOS разделяют идентификаторы уведомлений по аккаунтам.

Входящий звонок другого аккаунта показывает уведомление с предложением переключиться. При переключении на этот аккаунт ядро передаёт его сохранённое состояние входящего звонка платформенному менеджеру. Переключение с аккаунта с незавершённым звонком блокируется: звонок нужно завершить. Одновременный разговор в нескольких аккаунтах не добавляется.

Настройки оформления и защиты приложения остаются настройками установки. Контакты, переписка, ключи, черновики и синхронизируемые настройки находятся в базе соответствующего аккаунта. Ограничение до 10 устройств относится к каждому серверному аккаунту; новый продуктовый лимит количества аккаунтов на установке не вводится.

## Проверка

В `core/src/accounts.rs` проверяются отдельные истории с одинаковым ID переписки, сохранение отложенного черновика в исходный аккаунт, отказ неизвестному локальному ID, фильтрация событий, уведомление другого аккаунта, выход из одной сессии и сохранение выбора после перезапуска. В `apps/desktop/tests/interactiontest.cpp` проверяются расположение кнопок, открытие переключателя, клавиатурный фокус и высота области устройств.

Команды проверки:

```text
cd core
cargo test --offline --lib

apps\desktop\build.cmd
apps\desktop\build\neochat_interactiontest.exe

cd apps/android
gradlew.bat --offline :app:compileDebugKotlin
```

Локально 23.10.2026 прошли 23 unit-теста ядра и 8 Qt-проверок; собраны Desktop Release, Android-ядро для `arm64-v8a` и `x86_64` и debug APK (`gradlew.bat --offline :app:assembleDebug`). Снимки окна настроек и увеличенной области устройств проверены в Qt offscreen при размере 973×742, без входа в серверный аккаунт.

Android-ядро собирается существующей командой `cargo ndk` из README клиента. В Windows нет Xcode: исходники iOS требуют сборки на macOS и проверки на iPhone/симуляторе. Локальные проверки хранения не заменяют проверку доставки между несколькими реальными аккаунтами, входящих звонков и уведомлений на физических устройствах.
