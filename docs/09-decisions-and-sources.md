# Решения, допущения и источники

Дата проверки внешних ограничений: **2026-10-19**. Версии инструментов не выбираются по памяти: точные поддерживаемые patch-версии фиксируются на M0 в коде сборки и lockfiles.

## Подтверждено пользователем

- Desktop Qt, backend Go, Android Kotlin, iOS-приложение для установки через Scarlet.
- Веб-клиент с общим дизайном Android добавлен в проектирование; текущая работа — макет и документы, без установки инструментов.
- V1: личные чаты, файлы и небольшие группы.
- Сквозное шифрование обязательно к публичному запуску.
- Обязательная отдельная VPN не нужна.

## ADR-001: нативные клиенты и один сервер

**Статус: предложено.** Qt Widgets выбран для небольшого набора модулей и прямой model/view-отрисовки. Android Views и UIKit дают нативные списки без общего web runtime. Это направление для экономии ресурсов; фактическое преимущество подтверждается benchmark, а не названием toolkit.

Один Go-сервис с PostgreSQL упрощает транзакционную доставку и эксплуатацию. Redis, Kafka, отдельный object storage и микросервисы не нужны для первого измеримого запуска. Цена решения — одна серверная точка отказа и необходимость проверенного восстановления; HA не обещается.

Основания: [Qt model/view](https://doc.qt.io/qt-6/model-view-programming.html), [QListView](https://doc.qt.io/qt-6/qlistview.html), [поставка Qt](https://doc.qt.io/qt-6/deployment.html), [конкурентный доступ PostgreSQL](https://www.postgresql.org/docs/current/mvcc.html).

## ADR-002: E2EE без самописного ratchet

**Статус: требование принято, библиотека условная.** Кандидат libsignal даёт общую криптографическую реализацию. Однако проект прямо предупреждает об отсутствии поддержки внешнего использования и нестабильности bridge API; лицензия AGPLv3 требует отдельного решения о лицензировании NeoChat.

Нельзя предполагать готовый стабильный Qt SDK или подменять проверку интеграции текстом «используем Signal Protocol». M0 должен дать работающий Qt bridge, Android/Swift-интероперабельность и воспроизводимую сборку. Общая криптография не означает общий UI или Go runtime в телефоне.

Основания: [libsignal README и лицензия](https://github.com/signalapp/libsignal), [спецификации Signal](https://signal.org/docs/). Дополнительные условия проверяются по [лицензированию Qt](https://doc.qt.io/qt-6/licensing.html) и [официальному описанию LGPL-обязательств](https://www.qt.io/development/open-source-lgpl-obligations). Этот документ не является юридическим заключением.

## ADR-003: маленькие группы через pairwise fanout

**Статус: предложено.** До 16 участников и 3 устройств на аккаунт. Каждое сообщение получает до 47 отдельных envelopes. Это позволяет сначала использовать один pairwise crypto path вместо одновременной интеграции второго группового протокола.

Цена — больше CPU, трафика и ciphertext-хранения; потолок группы не повышается без измерений. Доверенный состав, подписи владельца и гонки исключения требуют самостоятельной проверки прикладного слоя; библиотека pairwise encryption не решает их автоматически.

## ADR-004: HTTP как единственный долговечный путь

**Статус: предложено.** Send и sync по HTTPS, WebSocket/push только сигнализируют о новых событиях. Есть один outbox, один алгоритм retry и один cursor. Цена — дополнительный HTTP round trip при WS-подсказке; она включена в latency benchmark.

## ADR-005: iOS — стандартная IPA, Scarlet — канал установки

**Статус: предложено, уведомления требуют проверки.** Swift/UIKit выбран для нативного жизненного цикла и компактной поставки. Push зависит от конкретной подписи, App ID и entitlements. Из возможности установить IPA не следует возможность использовать наш APNs topic.

Основания: [документация Scarlet](https://docs.usescarlet.com/), [APNs registration](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns), [aps-environment](https://developer.apple.com/documentation/bundleresources/entitlements/aps-environment), [фоновые стратегии Apple](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app).

## ADR-006: локальная история и ограниченное серверное хранение

**Статус: предложено.** Локальная зашифрованная история без фиксированного срока; серверные envelopes и вложения — 30 дней. Новое устройство получает будущие сообщения. Облачного escrow ключей и восстановления старой истории через пароль нет.

Для локальной базы рассматривается SQLCipher; качество key storage и реальное наличие cipher backend проверяются отдельно. Основание: [SQLCipher](https://www.zetetic.net/sqlcipher/).

## ADR-007: браузерный UI и отдельная проверка E2EE

**Статус: веб-дизайн запрошен, стек предложен, криптоинтеграция открыта.** Для начала предлагаются TypeScript + Vite без обязательного UI-фреймворка и общий Go API. Браузер не подменяет нативные клиенты. IndexedDB и crypto worker требуют отдельной модели ключей и атомарности; Node bindings libsignal не являются браузерным SDK.

До публичного веб-запуска обязательны межплатформенные векторы и проверки нескольких вкладок, XSS, сессий и потери локального хранилища. План и первичные источники: [веб-клиент](10-web-client.md). Публичного plaintext-режима нет.

## Открытые вопросы до реализации соответствующего этапа

1. Лицензия продукта и совместимость с выбранными зависимостями. Исходники не публиковались и лицензия не назначалась.
2. Наличие Mac/Xcode, iPhone и управляемого signing profile с APNs. Если их нет, iOS push остаётся неподтверждённой функцией до M0.
3. Конкретный crypto commit, Qt bridge, файловый AEAD framing и подписываемые структуры.
4. Точные patch-версии SDK, минимальные ОС и фактическая стоимость runtime.
5. Домен, email для операций, ёмкость VPS и место внешних backups. Рабочий `.env` не копируется в документы.

Эти вопросы не мешают просмотреть проект и начать независимую часть M0. Они мешают объявить интеграцию шифрования, push или эксплуатацию готовыми без доказательств.
