# Продукт и границы v1

## Назначение

NeoChat нужен для повседневной переписки с компьютера и телефона: быстро открыть, написать, отправить файл и продолжить разговор после потери сети. Рабочее имя взято из папки проекта; существующий знак N с бумажным самолётом сохраняется.

## Подтверждённые требования

- Qt для компьютера, Go для backend, Kotlin для Android, клиент iOS с установкой IPA через Scarlet.
- Браузерная веб-версия с общим дизайном Android добавлена в проектирование 2026-10-19. Её публичный запуск требует того же E2EE и отдельного барьера M0 для браузерной интеграции.
- Личные чаты, файлы и небольшие группы в первой версии.
- E2EE обязательно до публичного запуска: сервер не получает ключи расшифрования переписки и вложений.
- Лёгкость означает ограниченные RAM, размер поставки, CPU, трафик и работу в фоне. [Методика](08-performance.md) задаёт проверяемые цели.

## Предложенные границы

- Первым desktop выпускается Windows 11 x64. Linux x64 и macOS arm64 добавляются после проверки сборки и хранилища ключей; Qt-код сразу не привязывать к WinAPI.
- Android: arm64, Android 9/API 28 и новее. iOS: iOS 16 и новее. Минимумы перепроверяются по выбранным SDK и криптобиблиотеке на M0.
- До 16 человек в группе, включая владельца; до 3 активных устройств у аккаунта.
- Текст до 4096 байт UTF-8; файл до 25 MiB исходного содержимого. Отдельные квоты ограничивают хранение и суточную загрузку.
- Начальная регистрация по одноразовому приглашению, username и парольной фразе. Нет SMS и обязательной загрузки адресной книги.
- Добавление контакта по точному username или QR; без публичного каталога пользователей.

## Состав первой версии

- Создание аккаунта, вход, выход, список устройств, отзыв доступа, офлайн-код восстановления аккаунта.
- Личные чаты и группы; владелец группы добавляет и исключает людей. Обычные участники могут выйти без присутствия владельца. Выход владельца архивирует группу для новых сообщений после явного предупреждения. Передача владения и сложные роли откладываются.
- Текст, ответ на сообщение, файл и изображение как вложение. Удаление только локальной копии; редактирование и удаление «у всех» не входят в v1.
- Локальная история, черновик, очередь отправки без сети, повторная доставка без дублей.
- Состояния «В очереди», «На сервере», «Доставлено», «Прочитано». Read receipts отключаемы; отсутствие receipt не означает недоставку.
- Поиск по локально доступной истории. Серверный поиск по содержимому невозможен в этой модели E2EE.
- Светлая/тёмная темы, клавиатура на desktop, масштаб текста, уведомления без содержимого сообщений по умолчанию.

## Следующие версии

Звонки, голосовые сообщения, большие группы, каналы, боты, федерация, стикерная платформа, автоматическая загрузка контактов и облачный перенос старой истории не включены в v1. Кнопка недавних звонков в макете не означает реализованный транспорт. Веб-клиент больше не относится к отложенным идеям: дизайн и подготовка входят в текущий план, а публичный выпуск зависит от [браузерных критериев E2EE](10-web-client.md).

## История и устройства

Первое устройство является основным и подтверждает добавление остальных. Новое устройство видит будущие сообщения после подтверждения; старая история автоматически не появляется. Потеря всех устройств и восстановление аккаунта создают новые ключи и не расшифровывают старую историю. Это явно объясняется в интерфейсе до регистрации и восстановления.

## Приёмка продукта

Нативные клиенты обмениваются E2EE-сообщениями и файлами; группа корректно переживает вступление, выход и исключение; офлайн-получатель догоняет события без дублей; отозванное устройство больше не получает новые данные. Публичная веб-версия совместима с ними по тому же протоколу и не использует серверное расшифрование. Поведение iOS с фоновой доставкой проверено на реальной подписи и описано пользователю без обещаний постоянного WebSocket в фоне. Веб не получает обещания постоянной фоновой работы закрытой вкладки.
