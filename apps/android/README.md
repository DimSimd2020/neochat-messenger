# NeoChat для Android

Kotlin-клиент на Android Views без Compose и WebView. Шифрование, хранилище, синхронизация и очередь отправки находятся в общем Rust-ядре (`core/`). Ядро подключено через JNI как `libneocore.so`.

- minSdk 26, targetSdk 35. Release APK — `arm64-v8a`; debug для эмулятора также поддерживает `x86_64`, если ядро собрано для обеих архитектур.
- Ключ базы SQLCipher: 32 случайных байта, обёрнутые AES-GCM-ключом из Android Keystore.
- Резервное копирование отключено (`allowBackup=false`, `dataExtractionRules`).
- Экран с кодом восстановления защищён `FLAG_SECURE`.
- Уведомления показывают только название чата, без текста сообщения.
- В 0.6.2: свайп ответа по всей строке сообщения; анимированный статус набора; смена фото профиля; выбор чатов удержанием и массовые действия; локальная очистка истории; компактный архив раскрывается потягиванием списка вниз и скрывается при возврате. Фото профиля требует обновления сервера с миграцией `0006_avatar.sql`.

## Сборка

Нужны JDK 17, Android SDK 35, NDK 26.3, Rust с целями `aarch64-linux-android` и `x86_64-linux-android`, `cargo-ndk`, `protoc`. Пути к инструментам на этой машине задаёт `E:/dev/env.sh`.

1. Соберите ядро в `jniLibs`. Обёртка `uperl.bat` нужна OpenSSL под Windows: Perl от Git с модулями из `E:/dev/perl5lib`, плюс обход ассемблера NDK r26 для SM3.

```bash
source /e/dev/env.sh
cd core
PERL=E:/dev/shim/uperl.bat PATH=/e/dev/shim:$PATH \
  cargo ndk -t arm64-v8a -t x86_64 --platform 26 -o ../apps/android/app/src/main/jniLibs build --release --lib
```

2. Соберите APK. Подпись хранится вне репозитория, в файле свойств с полями `storeFile`, `storePassword`, `keyAlias`, `keyPassword`:

```bash
cd apps/android
NEOCHAT_SIGNING=E:/dev/keys/signing.properties ./gradlew assembleRelease
# app/build/outputs/apk/release/app-release.apk
```

Без `NEOCHAT_SIGNING` release-сборка подписывается sideload-ключом из `keystore/`. Им подписаны все опубликованные версии, поэтому пакет для автообновления собирается именно так: с другим ключом Android не установит обновление поверх. Debug-сборка: `./gradlew assembleDebug`.

## Проверка

Проверка на эмуляторе `Medium_Phone_API_36.1` (x86_64) против рабочего сервера:

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
adb shell am start -n app.neochat/.ui.MainActivity
```

Второго участника можно запустить из ядра (`core/examples/peer.rs`):

```bash
cd core && cargo build --release --example peer
target/release/examples/peer <dir> register https://r1270286.s2566.vm.mydomain.zone:8443 boris_test
target/release/examples/peer <dir> send <username> "Привет"
target/release/examples/peer <dir> expect <username> "Ответ"
```

Пройденные шаги:
1. Регистрация. Код восстановления не попадает на снимок экрана.
2. Входящее сообщение и уведомление.
3. Ответ, статусы до «Прочитано».
4. Код безопасности в сведениях.
5. Вход на новом телефоне по паролю: ключи и переписка восстанавливаются из копии на сервере.
6. «Устройства → Сканировать QR-код»: запрос доступа к камере, превью Camera2, закрытие сканера и возврат из фона без сбоев. Декодирование ZXing проверено на кадре с выравниванием строк (row stride).

### Архив, текстовые вкладки и выделение (рабочая копия, 22.10.2026)

Фильтры чатов и вкладки профиля используют линзу нижней навигации: подъём при касании, движение и увеличение содержимого, возврат после отпускания. Длинная строка вкладок профиля сохраняет горизонтальную прокрутку. У архива добавлены круг прогресса вытягивания и короткое приземление; группы обозначены значком перед названием. Выбранные строки чатов и контактов сохраняют голубую заливку после отпускания.

Проверено на установленном эмуляторе `Medium_Phone_API_36.1`, x86_64, без сетевого аккаунта:

```powershell
.\gradlew.bat --offline --no-daemon assembleDebug assembleDebugAndroidTest lintDebug
adb -s emulator-5556 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5556 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5556 shell am instrument -w -e archive true app.neochat.test/app.neochat.ui.InteractionInstrumentation
```

Пройдены частичный и отменённый жесты архива, раскрытие и скрытие прокруткой, переход в архив и назад, очистка переходных слоёв, однократная отмена архивирования. Дополнительно проверены быстрые фильтры, значок группы при повторном использовании строки, постоянная заливка выделения и её снятие, reduced motion, подъём/отмена/выбор текстовой линзы, прокрутка к последней вкладке профиля. Промежуточные кадры проверены визуально. `lintDebug`: 0 ошибок, 81 предупреждение. `assembleRelease` и встроенный `lintVitalRelease` также пройдены; номер сборки остаётся 0.6.7.3 (21), это локальная проверочная сборка.

### Быстрая реакция, общее состояние, «Что нового» (0.6.3)

На x86_64, API 36.1, против локального сервера проверены:
- двойное касание пустой части строки ставит реакцию, выбранную на другом своём устройстве; одиночное касание по-прежнему открывает меню;
- имя контакта и закреп чата проходят между телефоном и вторым устройством в обе стороны;
- после свежего входа окно «Что нового» не показывается, после обновления с 0.6.2 показывается один раз, с пунктами для Android.

Второе устройство того же аккаунта даёт `core/examples/peer.rs`: `peer <dir> login <server> <user> <password>`, затем `peer <dir> call <метод> '<json>'`.

### Звонки и фоновая доставка (0.6.3)

Debug-сборка принимает адрес тестового сервера; release всегда использует встроенный:

```bash
adb shell am start -n app.neochat/.ui.MainActivity --es test_server http://10.0.2.2:8098
```

Второй участник со звонками — ПК-сценарий `phonePeer` (см. [README ПК](../desktop/README.md)). На x86_64, API 36.1 проверены:
- аудиозвонок с телефона на ПК;
- ответный видеозвонок с ПК: кадры камеры эмулятора видны на ПК;
- входящий в свёрнутом приложении: heads-up с кнопками «Отклонить» и «Ответить», ответ из уведомления;
- записи о звонках в чате;
- сообщение в фоне при принудительном Doze: уведомление приходит сразу через `RealtimeService`.

## Ограничения

- В рабочей копии добавлен FCM: локальный `google-services.json` и SDK подключены, серверный отправитель и очередь реализованы. На Pixel 8 / Android 17 проверены два E2EE-сообщения и уведомление входящего звонка без фонового WebSocket, включая принудительный Doze и запуск процесса через push. Исправлен crash при включении FID auto-init из главного потока: [настройка и результаты](../../docs/19-firebase-push.md). Служба «NeoChat на связи» (foreground service `remoteMessaging`) с фоновым WebSocket продолжает работать независимо от FCM.
  - Службу можно выключить в «Настройки → Уведомления → Мгновенная доставка». При доступном FCM сообщения и звонки приходят через push; без push сообщения забирает периодическая задача JobScheduler.
  - Производители с агрессивной экономией батареи могут останавливать службу. Для этого в настройках есть пункт «Работа в фоне».
  - После перезагрузки служба запускается сама. Android 12+ может запретить запуск из фона, тогда служба стартует при следующем открытии приложения.
- «Устройства → Сканировать QR-код» впускает компьютер, который показывает QR-код на экране входа (Camera2 и ZXing core, разрешение `CAMERA` запрашивается при первом нажатии).
- Размытие стекла заменено полупрозрачной заливкой с контуром. Такую замену разрешает спецификация.
- Звонки только один на один. Для входящего в фоне нужен доступный FCM или работающая служба «NeoChat на связи»; при принудительной остановке приложения через настройки Android требуется снова открыть его.
